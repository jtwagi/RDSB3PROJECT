Phase 6 — SQL Server Backup Maintenance Plans, Cleanup & Job Notifications
Objective

The objective of Phase 6 was to configure automated database backup maintenance across the three SQL Server instances using SQL Server Maintenance Plans and SQL Server Agent.

The project requires three different backup strategies:

RDSB3MP1 on RDSB3SERVER1: Full backup of RDSB3DATABASE11 every Sunday at 10:00 PM.
RDSB3MP2 on RDSB3SERVER2: Differential backup of RDSB3DATABASE22 every six hours daily.
RDSB3MP3 on RDSB3SERVER3: Transaction-log backup of RDSB3DATABASE33 every 15 minutes.

Each maintenance plan also required a Maintenance Cleanup Task, with different retention periods, and SQL Server Agent notifications to the designated operators.

6.1 Backup Directory Preparation

Dedicated local backup directories were used to separate backup files generated by each SQL Server instance.

C:\SQLBackups\RDSB3SERVER1
C:\SQLBackups\RDSB3SERVER2
C:\SQLBackups\RDSB3SERVER3

Keeping the backup files separated by SQL Server instance makes administration, troubleshooting, retention management, and later restore testing easier.

The backup tasks were configured to create individual backup files on disk rather than combining multiple databases into a single backup destination.

6.3 MP1 Maintenance Cleanup

A Maintenance Cleanup Task was placed after the Full Backup task.

The workflow therefore became:

[Full Database Backup]
          |
          v
[Maintenance Cleanup]

The green precedence constraint ensures that the cleanup task executes after successful completion of the backup task.

The final cleanup configuration is:

File type:       Backup files
Folder:          C:\SQLBackups\RDSB3SERVER1
Extension:       bak
Retention:       Older than 3 weeks

The 3-week retention period matches the project specification.

Because differential backups depend on a full backup baseline, an initial full backup of the database was created before validating the differential maintenance plan.

BACKUP DATABASE RDSB3DATABASE22
TO DISK = 'C:\SQLBackups\RDSB3SERVER2\RDSB3DATABASE22_INITIAL_FULL.bak'
WITH
    INIT,
    CHECKSUM,
    STATS = 10;
GO

The backup folder subsequently contained the initial full backup and differential backup files generated by the maintenance job.

6.9 SQL Server Agent Notifications

The project requires maintenance-plan job success/failure notifications to designated operators:

RDSB3MP1 → RDSB3OPERATOR11
RDSB3MP2 → RDSB3OPERATOR22
RDSB3MP3 → RDSB3OPERATOR33

Database Mail had already been configured and tested in the previous phase, so SQL Server Agent was configured to use:

Mail system: Database Mail
Mail profile: RDSB3DBMPRO

The Agent jobs were then configured through:

SQL Server Agent
→ Jobs
→ Job Properties
→ Notifications

During testing, we selected:

E-mail: [Operator]
When the job completes

This was particularly useful for the project because it allowed successful executions to generate visible email evidence.

We initially tested When the job fails on MP2. Because the job succeeded, no email was generated—which is expected behavior. Changing the test notification to When the job completes resulted in a successful email notification.

6.11 Backup File Verification

The physical backup directories were inspected after execution.

For example, the SERVER3 directory contained an initial full backup plus subsequent transaction-log backups:

C:\SQLBackups\RDSB3SERVER3

RDSB3DATABASE33_INITIAL_FULL.bak
RDSB3DATABASE33_backup_... .trn
RDSB3DATABASE33_backup_... .trn

Two transaction-log files appeared close together during testing because MP3 was manually executed shortly before a scheduled execution.

The first execution occurred around 5:59 PM, while the recurring SQL Server Agent schedule executed again at approximately 6:00 PM.

Therefore, two transaction-log backup files were generated.

This also produced two MP3 notification emails.

At approximately the same time, the six-hour MP2 schedule executed automatically, producing an additional MP2 email. This provided useful evidence that SQL Server Agent was executing the maintenance plans independently according to their configured schedules.

6.12 Backup Integrity Verification

Backup creation alone does not prove that SQL Server can read the resulting backup set, so backup integrity was additionally checked.

RESTORE VERIFYONLY
FROM DISK = 'C:\SQLBackups\RDSB3SERVER2\RDSB3DATABASE22_INITIAL_FULL.bak'
WITH CHECKSUM;
GO

The verification returned:

The backup set on file 1 is valid.

Backup job succeeded
        ≠
Guaranteed recoverability

A production-grade backup strategy should therefore include periodic restore testing in addition to backup-job monitoring.
